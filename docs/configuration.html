api/proxy.js 详解

这是整个项目的核心文件，负责接收请求、转发到 GitHub、处理响应。

白名单配置

const ALLOWED_PREFIXES = [ 'github.com', 'api.github.com', 'raw.githubusercontent.com', 'codeload.github.com', 'objects.githubusercontent.com', 'camo.githubusercontent.com', 'avatars.githubusercontent.com', 'gist.github.com', 'github.githubassets.com', 'user-images.githubusercontent.com', 'private-user-images.githubusercontent.com' ];

只有匹配这些前缀的请求才会被代理，其他路径一律返回导航页。

💡 提示：新增域名时，记得同时更新 ALLOWED_PREFIXES、prefixes（路由匹配）、replaceText（HTML 文本替换）和 fixScript（客户端 JavaScript 劫持）四处。

关键函数说明

函数作用
isAllowedHost(host)判断目标域名是否在白名单内
replaceText(text)将 HTML 中的绝对 URL（含协议相对 URL）替换为代理相对路径
extractRepoInfo(path)从路径中提取 owner/repo
extractBranch(path)从路径中提取当前分支名
injectDownloadBtn(html, host, path)在页面右下角注入下载按钮
p(u)fixScript 核心：重写绝对、协议相对、根相对 URL，以及 fetch/XHR

请求头处理

// 删除的头部（防止冲突） 'host' → 由代理自动设置 'cf-connecting-ip' → Cloudflare 私有头 'x-vercel-id' → Vercel 内部头 'connection' → 连接管理头 'content-length' → 由运行时自动计算（解压后长度变化） // 设置的头部 'Host' → 目标域名（如 github.com） 'Origin' → https://目标域名 'Referer' → https://目标域名/ 'User-Agent' → 浏览器 UA（如未提供）

响应头处理

// 删除的头部（防止安全问题） 'content-security-policy' → 会阻止注入的脚本 'content-security-policy-report-only' → 同上 'clear-site-data' → 清除浏览器数据 'content-encoding' → 避免解压问题 'transfer-encoding' → 由运行时处理 // 添加的头部 'Access-Control-Allow-Origin' → *（允许跨域）

vercel.json 详解

{ "rewrites": [ { "source": "/(.*)", "destination": "/api/proxy" } ] }

这个配置将所有请求（无论路径是什么）都重写到 /api/proxy，由我们的代理函数统一处理。

字段含义
rewrites定义 URL 重写规则
source匹配模式，/(.*) 匹配所有路径
destination目标路径，指向代理函数

可选：添加 Headers 规则

{ "rewrites": [ { "source": "/(.*)", "destination": "/api/proxy" } ], "headers": [ { "source": "/(.*)", "headers": [ { "key": "X-Content-Type-Options", "value": "nosniff" }, { "key": "X-Frame-Options", "value": "DENY" }, { "key": "Referrer-Policy", "value": "no-referrer" } ] } ] }

package.json 详解

{ "name": "github-proxy", "version": "1.0.0", "private": true }
字段说明
name项目名称，Vercel 用它来命名部署
version语义化版本号
private设为 true 防止意外发布到 npm
⚠️ 注意：不要添加 "type": "module"，因为我们使用 CommonJS 的 module.exports 语法。混用会导致 Vercel 运行时报错。

请求头配置

代理在转发请求时会设置以下关键头部：

头部值作用
Host目标域名告诉上游服务器请求的目标
Originhttps://目标域名绕过 CORS 检查
Refererhttps://目标域名/模拟浏览器来源
User-AgentChrome UA避免被识别为爬虫

环境变量

当前版本不需要环境变量。如果需要添加（如 API Token），在 Vercel Dashboard → Settings → Environment Variables 中配置。

示例：添加 GitHub Token 支持

// 在 proxy.js 中读取 const token = process.env.GITHUB_TOKEN; if (token) { headers['Authorization'] = `Bearer ${token}`; }

然后在 Vercel 中添加环境变量 GITHUB_TOKEN，值为你的 GitHub Personal Access Token。这样可以提高 API 速率限制（从 60次/小时 提升到 5000次/小时）。

高级配置

1. 添加请求日志

// 在 handler 开头添加 console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`);

2. 限制请求大小

// 在读取 body 前添加 const contentLength = parseInt(req.headers['content-length'] || '0'); if (contentLength > 4.5 * 1024 * 1024) { return res.status(413).send('Payload too large (max 4.5MB)'); }

3. 添加速率限制

// 简单的 IP 速率限制（内存存储） const rateLimit = new Map(); const MAX_REQUESTS = 100; const WINDOW_MS = 60 * 1000; // 1 分钟 function checkRateLimit(ip) { const now = Date.now(); const windowStart = now - WINDOW_MS; const requests = rateLimit.get(ip) || []; const recent = requests.filter(t => t > windowStart); if (recent.length >= MAX_REQUESTS) return false; recent.push(now); rateLimit.set(ip, recent); return true; }

4. 缓存控制

// 对静态资源添加缓存头 if (contentType.includes('image/') || contentType.includes('font/')) { respHeaders['Cache-Control'] = 'public, max-age=86400'; // 1 天 } else if (contentType.includes('text/css') || contentType.includes('application/javascript')) { respHeaders['Cache-Control'] = 'public, max-age=3600'; // 1 小时 } else { respHeaders['Cache-Control'] = 'no-cache'; }
