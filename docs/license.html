📋 你需要遵守什么

MIT 许可证只有一个条件：

⚠️ 唯一条件：在分发代码时，必须包含原始的 LICENSE 文件和版权声明。就这么简单。

源代码文件头注释（推荐但不强制）

在每个源代码文件头部加上版权声明是好习惯：

// Copyright (c) 2026 tanle-mtr // Licensed under the MIT License - see LICENSE file

❌ 没有保障

MIT 许可证明确声明：

  • 不保证代码能用（"AS IS"）
  • 不保证适合任何特定用途
  • 作者不承担任何损害赔偿责任
  • 不保证没有 bug

换句话说：免费的东西，自己负责测试。

如何应用到你的项目

步骤一：创建 LICENSE 文件

在你的项目根目录创建名为 LICENSE（全大写）的文件，内容就是上方的 MIT License 文本。

步骤二：修改版权信息

把 Copyright (c) 2026 tanle-mtr 改成你的名字：

Copyright (c) 2026 你的名字或组织名

步骤三：在 README 中声明

## License Licensed under the [MIT License](./LICENSE).

步骤四：GitHub 自动识别

只要仓库根目录有 LICENSE 文件，GitHub 会自动在仓库主页右侧显示 "MIT License" 徽章。

场景是否允许注意事项

与 GPL 的区别

对比项MITGPL
修改后是否必须开源❌ 不需要✅ 必须
可以闭源商用✅ 可以❌ 不可以
条件数量1 个（保留声明）多个（传染条款）
适合场景库、工具、商用强调自由共享
💡 总结：MIT 是最宽松的开源许可证之一。你几乎可以用它做任何事，唯一的义务是保留版权声明。如果你不需要 GPL 的"传染性"，MIT 是最佳选择。
