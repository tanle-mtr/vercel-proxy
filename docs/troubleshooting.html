排查指南

系统化排查问题，从日志到代码逐层定位。

诊断脚本

运行以下脚本，一键诊断所有常见问题：

#!/bin/bash # diagnose.sh - GitHub 代理诊断脚本 # 用法: bash diagnose.sh https://your-domain.vercel.app DOMAIN="${1:-https://your-domain.vercel.app}" echo "🔍 GitHub 代理诊断报告" echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━" echo "域名: $DOMAIN" echo "时间: $(date '+%Y-%m-%d %H:%M:%S')" echo "" # 1. 基本连通性 echo "1️⃣ 基本连通性" CODE=$(curl -s -o /dev/null -w "%{http_code}" "$DOMAIN/" --max-time 10) echo " 根路径: HTTP $CODE (期望: 200)" if [ "$CODE" != "200" ]; then echo " ❌ 根路径异常！检查 Vercel 部署状态。" fi # 2. 代理功能 echo "" echo "2️⃣ 代理功能测试" CODE=$(curl -s -o /dev/null -w "%{http_code}" "$DOMAIN/github.com/vercel/next.js" --max-time 15) echo " GitHub 代理: HTTP $CODE (期望: 200/301/302)" if [ "$CODE" = "000" ]; then echo " ❌ 连接失败！可能是超时或 DNS 问题。" fi # 3. API 代理 echo "" echo "3️⃣ API 代理测试" CODE=$(curl -s -o /dev/null -w "%{http_code}" "$DOMAIN/api.github.com/repos/vercel/next.js" --max-time 15) echo " API 代理: HTTP $CODE (期望: 200)" if [ "$CODE" = "403" ]; then echo " ⚠️ 可能被 GitHub 限速，配置 GITHUB_TOKEN 解决。" fi # 4. 下载测试 echo "" echo "4️⃣ 下载测试" CODE=$(curl -s -o /dev/null -w "%{http_code}" "$DOMAIN/github.com/vercel/next.js/archive/refs/heads/canary.zip" --max-time 30) echo " Archive 下载: HTTP $CODE (期望: 200)" if [ "$CODE" = "200" ]; then SIZE=$(curl -s -o /dev/null -w "%{size_download}" "$DOMAIN/github.com/vercel/next.js/archive/refs/heads/canary.zip" --max-time 30) echo " 下载大小: $((SIZE / 1024)) KB" fi # 5. 速率限制 echo "" echo "5️⃣ GitHub API 速率限制" RATE=$(curl -s "$DOMAIN/api.github.com/rate_limit" 2>/dev/null) if [ -n "$RATE" ]; then echo "$RATE" | jq -r '" 限额: \(.resources.core.limit)\n 剩余: \(.resources.core.remaining)\n 重置: \(.rate.reset | strftime("%Y-%m-%d %H:%M:%S"))" 2>/dev/null else echo " ⚠️ 无法获取速率限制信息" fi echo "" echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━" echo "✅ 诊断完成。如有异常，请查阅下方对应章节。"

使用方法

# 保存脚本 cat > diagnose.sh << 'EOF' # (粘贴上面的脚本内容) EOF # 赋予执行权限 chmod +x diagnose.sh # 运行（替换为你的域名） ./diagnose.sh https://your-domain.vercel.app

500 错误处理

FUNCTION_INVOCATION_FAILED 是最常见的 500 错误。

排查步骤

  1. 查看日志：Vercel Dashboard → Functions → 选择部署 → 查看日志
  2. 本地复现：使用 vercel dev 在本地运行，看详细错误
  3. 检查语法：运行 node --check api/proxy.js 检查语法

常见原因和修复

错误信息原因修复
Invalid URLnew URL() 缺少 base使用 new URL(req.url, 'http://' + host)
.get is not a function把 req 当成了 Request 对象使用 req.headers['host'] 而非 req.headers.get()
.length is not a function把字符串当成了数组用 str.length（属性）而非 str.length()（函数）
Unexpected tokenJSON 文件有语法错误运行 json_pp < vercel.json 检查
MODULE_NOT_FOUND缺少依赖本项目零依赖，检查是否有 require() 调用

404 错误处理

场景原因修复
所有路径都 404vercel.json 重写规则未生效检查 vercel.json 格式是否正确
部分路径 404路径不在白名单中检查 URL 是否以 /github.com 等前缀开头
只有根路径 200正常行为根路径返回导航页，其他路径需带白名单前缀

调试 vercel.json

# 验证 JSON 格式 cat vercel.json | json_pp # 正确格式 { "rewrites": [ { "source": "/(.*)", "destination": "/api/proxy" } ] }

超时处理

超时类型默认限制解决方案
函数执行超时10 秒（Hobby）升级 Pro（300 秒）或用 aria2c 分片
上游连接超时无明确限制GitHub 限速，重试或换时段
浏览器等待超时~30 秒页面太大，等待或刷新

客户端超时设置

# cURL 设置超时 curl --connect-timeout 30 --max-time 300 "URL" # aria2c 设置超时 aria2c --connect-timeout=30 --timeout=300 "URL" # Wget 设置超时 wget --timeout=300 "URL"

下载失败

症状原因解决方案
下载中断Vercel 10 秒超时用 aria2c 多线程分片下载
文件损坏传输中断用 aria2c -c 断点续传
下载极慢路由不佳或限速换时段或升级 Pro
大文件失败超过 4.5MB 请求体限制仅影响上传，下载不受影响

速度慢

排查步骤

# 1. 测试到 Vercel 的速度 ping your-domain.vercel.app # 2. 测试下载速度 curl -o /dev/null -w "%{speed_download} bytes/s\n" "URL" # 3. 对比直连 GitHub 的速度 curl -o /dev/null -w "%{speed_download} bytes/s\n" "https://github.com/owner/repo/archive/main.zip" # 4. 测试不同地区节点（使用 Cloudflare Speed Test） curl "https://speed.cloudflare.com/__down?bytes=100000000" -o /dev/null -w "%{speed_download}\n"

提速方案

  • ✅ 使用 aria2c 16 线程（立竿见影）
  • ✅ 升级 Vercel Pro（300 秒超时）
  • ✅ 选择离你近的 Vercel 区域（Settings → Regions）
  • ✅ 避开高峰时段（国内晚上 8-11 点通常较慢）

日志检查

Vercel Dashboard 查看

  1. 打开 vercel.com/dashboard
  2. 选择你的项目 → Functions 标签
  3. 选择最新部署 → 查看 Runtime Logs

Vercel CLI 查看

# 实时日志 vercel logs --follow # 最近 50 行 vercel logs --limit 50 # 过滤错误 vercel logs | grep -i "error\|fail\|500" # 过滤特定路径 vercel logs | grep "github.com/vercel"

日志中的关键信息

日志内容含义
FUNCTION_INVOCATION_FAILED函数执行失败（代码错误）
FUNCTION_PAYLOAD_TOO_LARGE请求体超过 4.5MB
FUNCTION_TIMEOUT执行超过 10 秒
Proxy Error: TypeError代码中有类型错误
Bad Gateway上游 GitHub 无响应

重置部署

当一切都不对劲时，彻底重置：

# 1. 删除 Vercel 项目 vercel remove your-project-name # 2. 删除 GitHub 仓库（在 GitHub Web 上操作） # Settings → Danger Zone → Delete repository # 3. 创建全新仓库并推送 mkdir github-proxy-new cd github-proxy-new # 放入 api/proxy.js, vercel.json, package.json git init && git add . && git commit -m "init" git remote add origin git@github.com:user/new-repo.git git push -u origin main # 4. Vercel 重新导入

终极手段

如果以上都无效，考虑替代方案：

方案 A：Cloudflare Workers

边缘计算平台，天然适合做反代，不需要 JS 劫持。

  • 免费额度：10 万次请求/天，无限带宽
  • 支持 WebSocket
  • 可以完美反代 SPA（在边缘层改写，不需要浏览器端 JS）
  • 部署简单：wrangler publish 一行命令

方案 B：自建服务器

用 Nginx 反向代理，完全可控：

# Nginx 反代配置示例 server { listen 443 ssl http2; server_name proxy.example.com; location / { proxy_pass https://github.com; proxy_set_header Host github.com; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header Authorization ""; # 不传递认证 } }

方案 C：使用现成工具

  • ghproxy.cc — 国内可用的 GitHub 代理
  • ghproxy.cn — 另一个选择
  • git config --global url."https://ghproxy.cc/".insteadOf "https://github.com/" — Git 全局替换
💡 最后建议：如果下载是核心需求，Vercel 代理 + aria2c 多线程是最佳组合。如果网页浏览是核心需求，直接迁移到 Cloudflare Workers。
